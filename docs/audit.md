# Аудит TF3 Planner (2 октября 2026)

Проверено: все модули `tf3planner/`, тесты, мод, данные `data/`, логи прогонов, центр управления. Сверка — с
`docs/mechanics.md` (механики, проверенные по коду игры) и памятью проекта.

## 1. Итог

**Свою задачу — дать пошаговый, реально выполнимый план — приложение выполняет на 1900–1922 годы, но не до 2030-го.**

* Сильные стороны: формулы дохода, производства, кредитов и цен совпадают с кодом игры. По каждой линии есть
  подробный разбор — точки станций, депо, трасса по участкам, техника, настройки линии. ID в плане согласованы. GUI в
  один клик работает.
* До аудита план был сильно завышен: в 1910 году — доход 330 млн/год, на деле реалистичны ~73 млн. Причины —
  четыре ошибки учёта, из-за которых часть дохода считалась дважды или появлялась из ничего, и ошибка денежной модели.
  Все исправлены, подробности в разделе 3.
* Последняя выгрузка из игры (15:55) впервые содержит граф существующих дорог. С ним маршрутизатор строил объезды
  длиной в среднем ×2,5 от прямой, а в худшем случае ×32. Исправлено.
* Главный оставшийся пробел: модель мира статична. Города, спрос и пассажиропоток не растут, техника и пути не
  модернизируются по эпохам. Поэтому после ~1922 года план почти пуст, а деньги копятся миллиардами. До 2030-го нужна
  модель роста городов и модернизации (раздел 6).

## 5. Оптимальность

* **Цель MILP.** В каждом январе `flow.design` перестраивает целевую сеть с учётом уже построенного (оставшийся
  потенциал — 19–27 млн/год после платы за капитал). Прямые линии строятся только из этой цели. Пассажиры, кольцевые
  маршруты и склады в MILP не входят — они конкурируют с ней по жадной оценке NPV/вложения. Поэтому план близок к
  оптимуму только внутри класса «прямые грузовые линии».
* **Порядок цепочек.** Сырьё → завод → город строятся по порядку: выход завода появляется в предложении только после
  поставки сырья. Целиком цепочку оценивает только MILP — у жадного выбора у первого звена нет «ценности продолжения».
* **Дубли.** Не найдены: сигнатура проекта плюс `_prune_generic`; повторные линии сливаются в `buy_vehicles`.
* **Конкуренция за сырьё.** Теперь учитывается корректно (пункты 1–3).
* **Ранний этап.** Связан лимитом в 4 кредита и долгим первым кругом. Возможное улучшение: досрочно гасить кредит с
  маленьким остатком, чтобы освободить слот под крупное новое предложение. Пока не сделано.
* **Плато после ~1922 года.** Оно не про оптимизацию: к этому моменту модель уже выбрала весь статичный спрос
  (подробнее в разделе 6).

## 6. Что осталось — по приоритету

1. **Рост городов и спроса** — нужен для горизонта 2030. Каждый январь пересчитывать уровень города:
   * опыт XP = Σ доставленных единиц × 10·2^tier × xpFactor плюс пассажиры (`mechanics.md` §9.2–9.3);
   * ёмкость = начальная × F(l), отсюда спрос `TOWN_DEMAND_PER_CAPACITY × capacity` и население для
     `passengers.demand_matrix`;
   * уровни сверять с выгрузкой (`towns_stats` в экспорте v5+).

   Тот же прирост населения даёт ранг по `xpForRank` из экспорта — это заменит допущение `RANK_YEARS = 4` и будет
   согласовано с моделью. Сейчас ранг растёт, а население нет, — несогласованность.
2. **Модернизация по эпохам.** Ежегодно пересчитывать технику и для общих проектов: генератор по той же сигнатуре с
   бесплатными станциями — допустимо для пассажиров. Для грузовых проектов нужна переоценка при том же объёме, а не
   при свободном остатке. Отдельно — проекты апгрейда путей (стандартный путь 1930+, электрификация 1921+, дороги
   1940+): стоимость перестройки против выигрыша во времени круга по `dynamics`.
3. **Слой пропускной способности для общих проектов:** `capacity.apply_capacity` по участкам кольцевых маршрутов и
   плеч складских цепочек — пул ТО, терминалы, разъезды. Это заодно сведёт цены плана и разбора линий.
4. **Калибровка по игре** — как только появятся линии: число поездок на жителя (Q10; от этого ~16 % дохода — пассажиры),
   время погрузки (Q5), фактический рост ранга, деньги в минусе (можно ли и что за это бывает).
5. Слоты кредитов (рефинансирование), цена автостанции (п. 17), правило оплаты при перевалке (Q12).
